# Самопомощь

Веб-сервис психологической самопомощи, разработанный в рамках выпускной
квалификационной работы. Позволяет вести дневник состояния, проходить
стандартизированные опросники тревоги и депрессии (GAD-7 и PHQ-9), получать
рекомендации по техникам когнитивно-поведенческой терапии, отслеживать динамику
состояния и при необходимости оформлять заявку к специалисту.

Текущая версия является рабочим прототипом (MVP).

## Возможности

- Регистрация и вход в личный кабинет. При регистрации фиксируется согласие на
  обработку персональных данных в соответствии с ФЗ-152: сохраняются временная
  метка и контрольная сумма документа согласия.
- Дневник состояния: текстовые записи и оценка настроения. По каждой записи
  определяется эмоциональная окраска, отмечаются возможные когнитивные
  искажения и триггеры, подбирается подходящая техника КПТ.
- Экспресс-опросники GAD-7 и PHQ-9 с автоматическим подсчётом баллов и
  интерпретацией степени выраженности тревоги и депрессии.
- Динамика состояния: графики настроения и результатов опросников.
- Каталог специалистов и оформление заявки на консультацию.
- Сводный отчёт по данным пользователя.
- Экстренные контакты при выявлении кризисных признаков.
- Светлая и тёмная темы оформления, адаптивная вёрстка для мобильных устройств.

## Технологии

Серверная часть написана на Python 3.12 с использованием только стандартной
библиотеки (модуль `http.server` и встроенная база данных SQLite), поэтому
приложение запускается без установки дополнительных зависимостей. Работа с
данными вынесена в отдельный слой, что позволяет в дальнейшем заменить SQLite
на PostgreSQL без изменения остального кода. Для перехода на стек FastAPI
подготовлен файл `requirements-fastapi.txt`.

## Запуск

```
python server.py
```

После запуска приложение доступно по адресу http://127.0.0.1:8000. База данных
SQLite создаётся автоматически в каталоге `data/`.

Параметры запуска задаются переменными окружения: `HOST` (по умолчанию
`127.0.0.1`), `PORT` (по умолчанию `8000`), `DATABASE_PATH` (путь к базе
данных). Пример:

```
HOST=0.0.0.0 PORT=8080 python server.py
```

## REST API

Публичные запросы: регистрация, вход, список экстренных контактов, вопросы
опросников, каталог техник и специалистов.

Запросы, требующие авторизации (`Authorization: Bearer <token>`): профиль,
выход, дневник, отправка результатов опросника, заявки специалисту, динамика
и сводный отчёт.

Список основных маршрутов:

- `POST /api/register`, `POST /api/login`, `POST /api/logout`, `GET /api/me`
- `GET /api/crisis`
- `GET /api/tests/gad7`, `GET /api/tests/phq9`, `POST /api/tests/submit`
- `GET /api/diary`, `POST /api/diary`
- `GET /api/techniques`, `GET /api/psychologists`, `POST /api/requests`
- `GET /api/progress`, `GET /api/report`

## Развёртывание

### Облачный хостинг (Render)

Для постоянного доступа из интернета можно использовать бесплатный тариф Render.

1. Создать репозиторий на GitHub и отправить в него исходный код.
2. Войти на render.com через GitHub.
3. Создать Web Service, указав репозиторий, и команду запуска `python server.py`
   (или подключить файл `render.yaml` как Blueprint).
4. Render задаёт порт автоматически; приложение читает его из переменной
   окружения `PORT`.

Следует учитывать, что на бесплатном тарифе файловая система эфемерна: база
SQLite сбрасывается при повторном развёртывании, а сервис переходит в режим
сна после периода неактивности. Для постоянного хранения данных можно
подключить PostgreSQL.

### Временный доступ без VPN (туннель)

Домены облачных хостингов (например, `onrender.com`) могут быть недоступны без
VPN. Для демонстрации в такой ситуации удобно опубликовать локальный сервер
через туннель: публичный адрес будет открываться без дополнительных настроек.

Подготовлены готовые скрипты:

1. `start-server.cmd` — запускает сервер в фоне.
2. `start-tunnel.cmd` — открывает туннель через сервис localhost.run (использует
   встроенный в Windows OpenSSH, устанавливать ничего не нужно). В окне появится
   ссылка вида `https://xxxx.app.lhr.life`.
3. `start-tunnel.ps1` — то же самое для PowerShell, а при наличии установленного
   `cloudflared` использует его.

Ссылка действует, пока открыто окно туннеля; при повторном запуске адрес
меняется. Кроме того, доступны cloudflared (`cloudflared tunnel --url
http://localhost:8000`) и ngrok (`ngrok http 8000`) — им требуется установка.

### Доступ в локальной сети

Запустить сервер с параметром `HOST=0.0.0.0` и открыть на другом устройстве в
той же сети адрес `http://<IP-компьютера>:8000`.

## Ограничения текущей версии

- Пароли хранятся в виде хэша SHA-256. Для промышленной эксплуатации следует
  использовать bcrypt или argon2, а также токены JWT вместо Bearer-сессий.
- Сессии сохраняются в базе данных и переживают перезапуск сервера, однако
  механизм отзыва сессий со стороны сервера не реализован.
- Записи дневника не шифруются на диске.
- Сервис оказывает первичную поддержку и не заменяет консультацию специалиста.
  При выявлении кризисных признаков приложение показывает экстренные контакты
  и приостанавливает самопомощь.
